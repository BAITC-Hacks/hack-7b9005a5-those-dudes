# HackAlem «Граф денег» — локальный dashboard

Интерактивная визуализация всех трёх таблиц кейса:

- `nodes.parquet` — 2 248 узлов;
- `edges.parquet` — 3 119 направленных рёбер;
- `transactions.parquet` — 4 840 транзакций.

Граф, расчёты и общий чат работают локально без CDN. Опциональная кнопка объяснения
роли использует OpenAI только при настроенном ключе в корневом `.env`.

## Что визуализируется

- полный направленный граф с фильтрами по глубине, компоненте, кластеру и сумме;
- автоматическое центрирование и масштабирование после фильтрации, кнопки «+», «−», «Вписать граф»;
- поиск точного или частичного `gid`;
- карточка узла с входом, выходом, centrality и крупнейшими контрагентами;
- кнопка генерации объяснения назначенной роли, числовых оснований и неопределённости;
- PageRank по сумме и количеству, HITS, directed weighted betweenness;
- слабосвязные компоненты и Louvain-кластеры;
- дневной оборот и число транзакций;
- распределения сумм и повторяемость пар;
- FIFO-прохождение в тот же/следующий день, синхронные веера, reciprocal-пары и direct multi-seed;
- production-роли, уверенность, альтернативная роль, причины неопределённости и приоритет проверки;
- результаты кластеризации, resilience top-N, validation и сохранённые data-adaptive пороги;
- панель «AI-аналитик» с локальным `POST /api/query` и безопасным офлайн-fallback;
- полный журнал транзакций и постраничные таблицы данных;
- ограничения выборки: depth-4 цензура, изолированные seed и неполный баланс.

`build_dashboard.py` автоматически подхватывает доступные production-артефакты из `output/`:

- `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv`;
- `resilience.csv`, `features.csv`;
- `thresholds.json`, `run_metadata.json`, `validation_report.json` или `validation.json`;
- `node_details.json` и дополнительные CSV/JSON — без отключения raw-data views при отсутствии или ошибке отдельного необязательного файла.

При наличии `cluster_id` в `nodes_roles.csv` production-разбиение используется в сетевом фильтре и раскладке, а исходный Louvain остаётся в bundle как baseline.

## Запуск

Из корня репозитория:

```powershell
python -m pip install -r requirements.txt
python run_project.py
```

Открыть: <http://127.0.0.1:8765/>. Стартовая страница принимает три Parquet-файла, показывает ход анализа и автоматически открывает готовую панель. Можно также открыть сохранённый исходный набор.

Кнопка «Конкурсные 3 CSV» скачивает ZIP с `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv` с ровно 6/6/5 колонками и локальными объяснениями. «Расширенные CSV / AI» и меню отдельных файлов сохраняют дополнительные признаки и готовые API-абзацы. Все данные и запросы привязаны к `run` в ссылке. Для загрузки файлов, выбора набора и экспорта нужен backend проекта, а не обычный статический сервер или открытие HTML с диска.

## AI-аналитик

В карточке любого узла нажмите «Сгенерировать объяснение роли». Через
`POST /api/explain-node` backend получает строковый `gid`, собирает метрики и условия
назначения роли и генерирует пояснение. Ключ вводится только в `.env` на сервере,
а не в браузере. Без ключа или при ошибке API показывается явная ошибка, а не
имитация ответа модели. Генерация не изменяет роль и priority-score. В OpenAI передаются только
метрики выбранного узла без его идентификатора, контрагентов и исходных переводов.

Раздел «AI-объяснения для CSV» генерирует структурированные основания и полные
объяснения для всех узлов или top-списка после подтверждения расходов. Результаты
сохраняются и включаются в существующие кнопки CSV/ZIP. Частичные выгрузки явно
помечены; подробная схема — в [описании API-объяснений](../docs/api_evidence_exports.md).

Для запуска этой функции нужен `python run_project.py --skip-pipeline --skip-dashboard`
после установки `requirements-ai.txt`; обычный `python -m http.server` не поддерживает
новый процесс загрузки, выбор набора, экспорт и генерацию.

При запуске вместе с локальным agent backend панель отправляет JSON `{"question": "..."}` в `POST /api/query`. Она принимает структурированный локальный ответ (`message`, `data`, `warnings`, `caveat`) и совместима с ответами в полях `answer`, `response` или `result`.

Если endpoint недоступен, возвращает ошибку или dashboard открыт через `file://`, интерфейс явно переключается в офлайн-режим. В этом режиме никакой запрос наружу не отправляется: локально доступны карточка точного `gid`, top-priority, depth-4 ограничения и resilience summary.

## Обновление данных

Рекомендуемый путь — кнопка «Новый анализ» в панели и три поля на стартовой странице. Файлы на диске могут называться иначе, но должны соответствовать своим разделам и схеме. Лимиты и описание API: [процесс загрузки](../docs/upload_workflow.md).

По умолчанию скрипт читает `input_data/data`. Другой каталог можно передать явно:

```powershell
python dashboard/build_dashboard.py --data C:\path\to\data
```

Ожидаются файлы `nodes.parquet`, `edges.parquet`, `transactions.parquet` со схемой кейса.

## Важные технические решения

- `gid`, `src` и `dst` передаются в JavaScript как строки: числовые значения превышают безопасный диапазон JavaScript.
- Точные повторы строк в `transactions.parquet` не удаляются: без дополнительного идентификатора операции они могут быть реальными повторными переводами.
- FIFO-метрика сопоставляет каждую единицу наблюдаемого входа не более одного раза и не восстанавливает отсутствующие потоки.
- Полный граф рисуется на Canvas; таблицы и управление остаются обычным доступным HTML.
- Координаты пересчитываются после изменения размера Canvas и возврата на вкладку. Выбранный кластер вписывается в область просмотра; карточку узла можно закрыть, чтобы освободить место.
- При выборе узла его непосредственные связи подсвечиваются, остальные уходят на второй план. Клавиши `+` / `−` меняют масштаб, `0` вписывает текущую выборку.
- Стрелки показываются только при увеличении или на небольших подграфах, чтобы 3 119 рёбер не превращались в визуальный шум.
- Louvain — навигационный baseline, а не утверждение о принадлежности узлов к организации.
