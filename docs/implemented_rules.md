# Действующие правила расчёта

Это описание **реализованного алгоритма**, а не исследовательские рекомендации. Роли — структурные гипотезы по неполной выборке, не вывод о нарушении. Приоритет и уверенность роли — разные показатели.

Единый источник условий допуска — `src/money_graph/rules.py:decision_trace`: его вызывают и scoring, и объяснитель. Веса профилей находятся в `PROFILE_TERMS` того же модуля; их фактические формулы сохраняются в `thresholds.json:profile_formulas`. Значения всех адаптивных порогов — в `thresholds.json`; значения признаков каждого узла — в `features.csv`. `*_extended.csv` сохраняют подробности для интерфейса и аналитика. Конкурсные CSV имеют ровно 6/6/5 колонок.

## Обозначения и пороги

`R(x)` — средний ранг среди **положительных** значений, делённый на их число; неположительные и пропуски получают 0. Все `p_*` ниже — такие ранги, не вероятности. Идентификатор `gid` не является признаком.

- `in_deg/out_deg` — разные отправители/получатели, `in_tx/out_tx` — число переводов.
- `in_flow_share = in_kzt/(in_kzt+out_kzt)`, аналогично для выхода. Это доли **оборота узла**, не всей сети.
- `retention = max(in_kzt-out_kzt,0)/in_kzt` при положительном входе; иначе 0. Это наблюдаемый дисбаланс, не остаток счёта.
- `balance_similarity = min(in_kzt,out_kzt)/max(in_kzt,out_kzt)` при обоих положительных потоках; иначе 0.
- `fifo_1d` — жадно сопоставленная сумма в тот же/следующий день, делённая на **меньший** из входящего и исходящего объёмов. Это не доказательство движения тех же денег; порядок внутри дня неизвестен.
- `brokerage` — среднее направленных обычной и взвешенной betweenness; `participation` — разнообразие кластеров контрагентов по долям сумм.
- `motif = mean(p_sync_in,p_sync_out,p_repeat_route,p_reciprocal,p_cycle)`.
- `pagerank_mean = mean(p_pagerank_amount,p_pagerank_count)`.
- `sync_out_present = 1[max_out_targets_day>0]*p_sync_out`; `no_continuation = 1-p_continue`.

Адаптивные пороги берутся только по положительным значениям **не-seed** узлов. `g_in = max(1,ceil(Q95(in_deg)-1e-12))`, `g_out = max(1,ceil(Q90(out_deg)-1e-12))`, `v_in = Q50(in_kzt)`. При пустой подвыборке используются соответственно 3, 8 и 50 000 KZT. Для исходного набора измерены 3 / 8 / 50 000 KZT; для новых файлов надо читать их собственный `thresholds.json`.

## Условия допуска

Все условия строки соединены **И**, кроме явно указанного **ИЛИ**.

| Роль | Условия |
|---|---|
| `consolidator` | Не seed; `in_deg>=g_in`; `in_flow_share>=0.80` |
| `transit` | Не seed; есть входы и выходы; **`fifo_1d>=0.80 ИЛИ balance_similarity>=0.80`** |
| `distributor` | `out_deg>=g_out`; `out_flow_share>=0.80`. Seed допускается |
| `terminal` | Не seed; входов больше нуля, выходов ноль; `in_kzt>=v_in`; `depth<4` **ИЛИ** (`truncated_by_depth` и `p_continue<=0.20`) |
| `coordinator` | Не менее 3 из 5 сигналов (`p_brokerage`, `p_seed_affinity`, `p_participation`, `pagerank_mean`, `motif`) >=0.90; `max(p_brokerage,p_participation)>=0.90`; профиль coordinator >=0.75. Seed допускается |
| `peripheral` | Всегда допускается; может выиграть даже при наличии другой допустимой роли |

Транзит по месячному сходству объёмов **не подтверждает быстрое прохождение**. Например, сочетание FIFO≈4,53% и сходства≈82,13% проходит вторую ветку условия; локальное evidence явно говорит, что быстрое прохождение не подтверждено. Конкретные значения не зашиты в классификатор.

## Формулы профилей

Эти строки соответствуют `PROFILE_TERMS`; регрессионный тест проверяет совпадение документа с общей конфигурацией.

| Роль | Профиль |
|---|---|
| consolidator | `0.25*p_in_deg + 0.20*p_in_tx + 0.20*p_in_kzt + 0.15*p_authority + 0.20*retention` |
| transit | `0.30*fifo_1d + 0.20*balance_similarity + 0.20*p_brokerage + 0.15*p_total_tx + 0.15*p_repeat_route` |
| distributor | `0.25*p_out_deg + 0.20*p_out_tx + 0.20*p_out_kzt + 0.15*p_hub + 0.20*sync_out_present` |
| terminal | `0.35*retention + 0.25*p_in_kzt + 0.15*p_in_tx + 0.15*p_authority + 0.10*no_continuation` |
| coordinator | `0.25*p_brokerage + 0.20*p_seed_affinity + 0.20*p_participation + 0.15*pagerank_mean + 0.20*motif` |
| peripheral | `clip(1-max(пяти остальных профилей),0.05,1)` |

Для профильной суммы retention, balance_similarity и fifo_1d ограничены диапазоном 0..1.

Основная роль — максимум профиля **среди допущенных ролей**. При равенстве используется порядок `consolidator, transit, distributor, terminal, coordinator, peripheral`. Вторичная — следующая допустимая; если такой нет, сохраняется лучший недопущенный непериферийный профиль только как альтернатива, а не второй подтверждённый вариант.

## Уверенность роли

`margin=max(0,основной_профиль-вторичный_профиль)`; при отсутствии второй допустимой роли вычитается указанная выше недопущенная альтернатива.

`role_score=clip(observability*(0.45*profile+0.30*min(1,margin/0.25)+0.25*stability),0.05,0.99)`.

`stability` — доля повторов той же роли при добавлении независимого нормального шума σ=0.035 к готовым профилям с **фиксированными условиями допуска**, обычно 40 повторов. Это не возмущение транзакций, не accuracy и не устойчивость ранжирования.

Множитель observability: 1 обычно; 0.85 для seed-coordinator; 0.70 при обрезанном выходе глубины 4; 0.55 для такого terminal; 0.45 для изолята (последнее условие имеет приоритет). Верхние границы: 0.60 для censored-terminal и 0.35 для изолированного seed. Даже observability=1 не означает полноту данных.

`p_continue` — вспомогательная L2-логистическая модель наличия **наблюдаемого** исходящего ребра по входным признакам на глубинах 1–3, не роль, не вина и не прогноз будущей активности. Обучение: не-seed, есть вход; только входные признаки, стандартизация по обучающей группе, IRLS до 100 шагов, L2=1 без штрафа intercept. При <20 строк или единственном классе — константа частоты выходов (0.5 при отсутствии обучающих строк). Метрики обучающей выборки описательные, не независимая оценка качества. Порог `terminal_continue_reject=0.50` сохранён для аналитической интерпретации; дополнительного gate с ним нет.

## Приоритет проверки

`K=.40*p_brokerage+.30*p_fragmentation+.30*p_participation`.

`E=.35*p_total_kzt+.25*p_total_tx+.40*max(p_pagerank_amount,p_pagerank_count,p_authority,p_hub)`.

`S=.55*p_seed_affinity+.30*p_direct_seed+.15*R(n_seed_reachable)`.

`T=.35*fifo_1d*R(min(in_kzt,out_kzt))+.25*max(p_sync_in,p_sync_out)+.20*max(p_repeat_route,p_repeat_edge)+.20*max(p_reciprocal,p_cycle)`; p_repeat_edge берётся от числа повторных **входящих** рёбер.

`X=max(пяти непериферийных профилей ДО фильтра допуска)`; `U=(1-role_score)*E`.

`priority_raw=.30*K+.22*E+.18*S+.15*T+.10*X+.05*U`.

`priority_score` — средний процентильный ранг priority_raw **среди всех узлов**, не вероятность. Малый U уменьшает его добавку, а не повышает приоритет. Top сортируется по priority_score убыв., затем priority_raw убыв., затем gid возр. При одинаковых рангах это обеспечивает повторяемость.

## Как разобрать любой узел

1. Найти его строку в `features.csv`, взять пороги из соседнего `thresholds.json`.
2. Проверить каждое условие таблицы, затем сравнить допустимые профили; учесть tie-break и peripheral.
3. Рассчитать margin, observability и role_score; отдельно сравнить взвешенные компоненты приоритета.
4. Проверить sampling-оговорки и альтернативу. Машинная трасса каждого узла в `decision_traces.json` содержит наблюдения, пороги и результаты всех проверок.

Сбор: четыре исходящих шага, порог суммы 5 000 KZT, конечное временное окно. Нулевой выход на глубине 4 не доказывает terminal; внешние входы seed неполны. Временные циклы ищутся длиной 2–6 со всеми поворотами и начальными датами, неубывающими датами и окном ≤7 дней. Один структурный цикл считается один раз, даже если временных реализаций несколько.
