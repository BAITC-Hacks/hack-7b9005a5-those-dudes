# Объяснения узлов через API и экспорт CSV

Для длинных API-абзацев используйте кнопку **«Расширенные CSV / AI»**. Отдельная кнопка **«Конкурсные 3 CSV»** отдаёт ровно 6/6/5 колонок с локальными русскими основаниями до 200 символов, без API. Эти режимы не заменяют друг друга.

Расчёт ролей остаётся детерминированным. Отдельный агент через OpenAI API объясняет уже назначенную роль и приоритет по сохранённым признакам, условиям допуска и профильным оценкам. Он не меняет роль, `role_score`, `priority_score`, кластер, ранг или исходные транзакции.

## Как использовать

1. Откройте готовый набор в dashboard.
2. Разверните **«AI-объяснения для CSV»**. Выберите все узлы либо список приоритетных узлов.
3. Подтвердите отправку обезличенных метрик и использование платного API, затем запустите генерацию.
4. Дождитесь заполнения покрытия. Остановка прекращает новые запросы; уже выполняющиеся запросы могут завершиться и использовать токены. Повторный запуск пропускает успешно сохранённые объяснения.
5. Нажмите **«Расширенные CSV / AI»** или отдельный CSV в меню. Они включают сгенерированные объяснения; конкурсная кнопка сохраняет строгую схему.

Кнопка объяснения в карточке отдельного узла использует тот же структурированный агент и сохраняет результат для CSV. Она не запускает обработку всех узлов. Просмотр страницы, загрузка Parquet, проверка статуса и скачивание CSV сами по себе не вызывают модель.

Нужны зависимости `requirements-ai.txt`, действующий `OPENAI_API_KEY` в `.env` и доступ к настроенному `OPENAI_MODEL`. Ключ не передаётся браузеру. Ошибка подключения, ключа, лимита, формата или проверки ответа отображается явно; локальный текст не выдаётся за API-ответ.

Это отдельный платный этап: он не входит в пятиминутный лимит локального анализа. Время зависит от числа узлов, модели, ограничений аккаунта и длины ответов. Одновременно выполняются не более трёх запросов. Есть ограниченный повтор временных ошибок и остановка при повторяющихся сбоях; автоматического бесконечного повтора нет.

## Колонки

В `nodes_roles.csv` и `top_nodes.csv` сохраняются обязательные исходные колонки и добавляются:

| Поле | Содержание |
|---|---|
| `evidence` | Связное объяснение на русском через OpenAI API: наблюдаемые факты, почему выбрана роль, ограничения; до **200 слов** |
| `why` | Связное объяснение через OpenAI API: что определяет приоритет и что проверить аналитику; до **200 слов** |
| `explanation` | Полное объяснение роли, допуска по правилам и ограничений |
| `priority_explanation` | Полное объяснение значимых компонентов приоритета; отдельно от уверенности роли |
| `evidence_json` | Структурированные основания: тип, точные ссылки на признаки, значения, единицы и интерпретация |
| `alternative_explanation` | Почему альтернативная роль слабее или не прошла условия допуска |
| `limitations` | Цензура, неполнота потоков и другие ограничения конкретного наблюдения |
| `analyst_next_step` | Следующая проверка, связанная с этой гипотезой |
| `explanation_source` | `openai`, `not_generated` или `error` |
| `explanation_status` | `complete`, `not_generated` или `error` |
| `explanation_model` | Модель для текущей версии объяснений |
| `explanation_error` | Безопасное описание ошибки, если она произошла |
| `explanation_error_code` | Код ошибки API или проверки ответа; без ключа и сырого ответа провайдера |
| `evidence_rule`, `why_rule` | Исходный краткий текст pipeline, если соответствующая колонка была в исходном CSV |

У незавершённых строк сохраняются исходные краткие основания; длинные API-поля пусты, а источник и статус явно показывают отсутствие генерации. Частичную выгрузку нельзя представлять как полностью объяснённую агентом. `clusters.csv` не меняется: это описание кластеров, а не запрос на объяснение узлов.

## Что проверяется

Лимит применяется отдельно к `evidence` и `why`: не более 200 слов после подстановки чисел и обязательных оговорок. Слова считаются по пробельным разделителям (части числа с пробелами тоже учитываются). Текст не обрезается: ответ сверх лимита отклоняется с явной ошибкой. Обычно модель пишет 60–120 слов до добавления оговорок. Числа в абзацах задаются проверяемыми ссылками `{{fact_id}}` и подставляются сервером; неизвестные ссылки и неразрешённые числовые литералы отклоняются. Технические формулы остаются в дополнительных полях, а не заменяют человеческое объяснение.

Это новый формат API-выгрузки по требованию пользователя (200 **слов**), отличный от исходного конкурсного лимита 200 **символов**. Краткие конкурсные основания сохранены в `evidence_rule` / `why_rule` и исходных CSV pipeline. Кэш старых коротких API-ответов не используется для нового формата: запустите генерацию заново и скачайте свежий снимок. Для объяснений всех строк выберите «Все узлы» и дождитесь полного покрытия.

Агент возвращает типизированный объект через `Agent(output_type=...)`. Схема каждого запроса ограничивает `fact_ids` каталогом именно этого узла, фиксирует назначенную роль и задаёт границы количества оснований. Числовые значения в итоговый текст и JSON подставляет сервер из локального каталога. Цифровые литералы в свободном тексте модели отклоняются: числа должны идти через ссылки на факты. Проверяются обязательные поля, длина текста, наличие оснований по роли и приоритету, неизменность роли и согласованность с трассой правил. Обязательные оговорки о границе depth=4, seed и неполном исходящем обходе добавляет сервер.

Числа в структурированных основаниях подставляет сервер. Запрет числовых литералов и инструкция не записывать наблюдаемые величины словами снижают риск выдуманных количественных утверждений, но не доказывают правильность естественно-языковой интерпретации. Модель получает словарь определений: например, доля входящего потока относится к обороту самого узла, а компонент неопределённости не измеряет стабильность приоритета. Объяснения — гипотезы для ручной проверки, не выводы о виновности и не достоверные сведения о ненаблюдаемых операциях.

Модель получает метрики одного узла, обезличенные ролевые решения, пороги и ограничения. `gid`, контрагенты, исходные строки транзакций и сохранённые свободные текстовые поля не отправляются. Внешнего поиска нет. SDK tracing отключён, Responses `store=False`; это не обещание отсутствия всех служебных журналов провайдера.

## Хранение и воспроизводимость

Готовые ответы и прогресс хранятся в `runtime/narratives/`, вне публичного каталога. Кэш зависит от точного содержимого признаков, модели и версии prompt/валидации. Изменение этих данных требует новой генерации; старый ответ не подмешивается к новому набору.

CSV и ZIP строятся как согласованные снимки на момент скачивания, с точными строковыми идентификаторами. Исходные файлы `output/` и `runtime/datasets/<run>/output/` не перезаписываются. Префиксы Excel-формул в генерируемом тексте обезвреживаются. `usage` показывает только известные приложению токены/попытки, а не денежный счёт провайдера.

## Локальный API

- `GET /api/explanations/status?run=<run_id>` — покрытие, прогресс, доступность модели и сохранённые ошибки.
- `POST /api/explanations/start?run=<run_id>` — JSON `{"scope":"all","consent":true}`; для ограниченного теста можно добавить положительный `limit`.
- `POST /api/explanations/cancel?run=<run_id>` — JSON `{}`.
- Для start/cancel обязателен `X-HackAlem-Action: explain-batch` и тот же origin.
- `POST /api/explain-node?run=<run_id>` — JSON со строковым `gid`, `X-HackAlem-Action: explain-node`.
- Существующие `/api/datasets/<run_id>/exports/...` возвращают дополненные CSV/ZIP без новых вызовов модели.
- Те же адреса с `?mode=contest` возвращают только фиксированную конкурсную схему из локальных результатов. Они не используют API-кэш.

Реализация опирается на официальные [типизированные ответы Agents SDK](https://developers.openai.com/api/docs/guides/agents/define-agents) и [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
