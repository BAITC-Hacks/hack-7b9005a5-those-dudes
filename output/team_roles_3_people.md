# Распределение работы на команду из 3 человек

## Общий принцип

Backend формирует единый источник истины — CSV и JSON с рассчитанными метриками. Frontend и AI-ассистент работают только через этот контракт, поэтому все трое могут разрабатывать параллельно.

### Общие контракты, согласовать за первые 20 минут

- `nodes_roles.csv` — роли, scores, evidence и базовые метрики.
- `clusters.csv` — характеристики кластеров.
- `top_nodes.csv` — расследовательский приоритет.
- `node_details.json` — временные признаки, соседние узлы, альтернативная роль, uncertainty.
- `graph.json` — узлы и направленные рёбра для интерфейса и AI-инструментов.

---

## 1. PM + Frontend

### Ответственность

Довести продукт до демонстрируемого состояния: определить MVP, собрать интерфейс, координировать интеграцию и подготовить презентацию.

### Задачи

**Управление**

- Зафиксировать критерии готовности и не допускать расширения scope.
- Согласовать схемы файлов и значения ролей.
- Проводить интеграционные checkpoints каждые 60–75 минут.
- Контролировать формулировки: только «гипотеза для проверки», без утверждений о виновности.
- Собрать README, архитектурную схему и пятиминутный сценарий демо.

**Frontend**

Сделать простой локальный интерфейс на Streamlit:

1. Top-N с фильтрами по роли, кластеру и минимальному приоритету.
2. Поиск по `gid`.
3. Карточка узла:
   - роль и уверенность;
   - priority-score;
   - числовое evidence;
   - альтернативная роль;
   - предупреждение о depth-4 цензуре.
4. Направленный ego-граф на 1–2 шага.
5. Входящие и исходящие суммы/транзакции.
6. Временная шкала переводов.
7. Карточка кластера и его гипотеза.
8. Панель AI-ассистента.

### Definition of Done

- Любой `gid` находится за несколько секунд.
- На схеме видны направление, роль, кластер и размер потока.
- Интерфейс работает даже без LLM/API.
- Подготовлены три демонстрационных кейса: consolidator, transit/distributor и censored depth-4.
- README содержит одну команду запуска.

## 2. Backend

### Ответственность

Полностью воспроизводимый data pipeline от трёх Parquet-файлов до ролей, кластеров, приоритетов и evidence.

### Задачи

**Загрузка и проверки**

- Проверить схемы, число строк и согласованность `edges` с `transactions`.
- Не потерять 19 изолированных seed.
- Зафиксировать random seeds и сохранить рассчитанные пороги.

**Признаки**

- In/out degree, суммы, число транзакций и активные дни.
- Amount- и count-PageRank.
- HITS hub/authority.
- Directed weighted betweenness.
- Seed connectivity и multi-seed признаки.
- FIFO pass-through за 0/1/2 дня.
- Синхронные fan-in/fan-out.
- Повторные маршруты, reciprocal edges и временно допустимые циклы.
- Cluster participation и removal impact.

**Роли и uncertainty**

- Реализовать шесть прозрачных role-score.
- Применить gate-условия и deterministic tie-breaking.
- Обучить простую continuation-модель для depth-4.
- Ограничить confidence censored-terminal значением 0,60.
- Формировать evidence до 200 символов с конкретными числами.

**Кластеризация и приоритет**

- Louvain/Leiden baseline.
- Directed Infomap, если успевает установка.
- Несколько random seeds и оценка ARI/VI.
- Рассчитать независимый priority-score.
- Построить resilience top-1/5/10/20/50.

**Экспорт и тесты**

- Создать три обязательных CSV.
- Дополнительно экспортировать `node_details.json`, `graph.json`, `thresholds.json`.
- Добавить schema, synthetic-motif и runtime smoke tests.

### Definition of Done

- Ровно 2 248 строк в `nodes_roles.csv`.
- Нет пустых ролей, scores или evidence.
- `top_nodes.csv` содержит минимум 20 отсортированных узлов.
- Ни одного hardcoded `gid`.
- Полный запуск занимает менее пяти минут.

## 3. Agentic AI

### Ответственность

Read-only AI-ассистент, который отвечает только по рассчитанному графу, вызывает детерминированные инструменты и показывает происхождение каждого числа.

### Инструменты агента

- `get_node(gid)` — роль, scores, evidence и uncertainty.
- `get_neighbors(gid, direction, hops)` — входящие/исходящие связи.
- `trace_flow(source, max_hops)` — наблюдаемые маршруты денег.
- `find_common_recipients(gids)` — общие получатели заданных узлов.
- `find_consolidators(gids)` — кандидаты на точки сбора.
- `explain_priority(gid)` — разложение priority-score.
- `compare_nodes(gids)` — табличное сравнение.
- `get_cluster(cluster_id)` — состав и числовая гипотеза кластера.
- `simulate_removal(gids)` — изменение связности после удаления.
- `list_uncertain_nodes()` — высокоприоритетные узлы с низкой уверенностью.

### Поведение агента

- Сначала вызывает инструмент, затем формирует ответ.
- Не использует внешние данные и не додумывает атрибуты клиентов.
- Для каждого вывода приводит `gid` и числовые основания.
- Различает роль, уверенность и расследовательский приоритет.
- Называет depth-4 цензуру и другие ограничения данных.
- Использует формулировки «наблюдаются признаки» и «кандидат для проверки».
- При отсутствии подтверждающих данных прямо отвечает, что вывод невозможен.
- Имеет шаблонный fallback без LLM, чтобы демо не зависело от API.

### Минимальные eval-сценарии

1. «Почему этот узел в top-20?»
2. «Кто получает деньги от нескольких указанных seed?»
3. «Покажи транзитные узлы с прохождением за один день».
4. «Что изменится после удаления этих пяти узлов?»
5. «Этот depth-4 узел действительно terminal?»
6. Проверка отказа на вопрос о виновности или отсутствующих клиентских атрибутах.

### Definition of Done

- Не менее пяти работающих инструментов.
- Ответы содержат только значения из pipeline.
- Для каждого вывода виден источник данных.
- Работает минимум пять подготовленных demo-запросов.
- Ошибка LLM/API не блокирует основной интерфейс.

## Параллельный график на 5 часов

| Время | PM + Frontend | Backend | Agentic AI |
|---|---|---|---|
| 0:00–0:20 | scope, UI wireframe, data contract | schema и контракт экспорта | список tools и формат ответов |
| 0:20–1:15 | интерфейс на fixture-файлах | базовые и графовые признаки | tool layer на fixtures |
| 1:15–2:15 | top-list, поиск, карточка узла | время, роли, censoring | graph-query tools и guardrails |
| 2:15–3:00 | граф и кластерная карточка | clustering и priority | agent orchestration и fallback |
| 3:00–3:40 | подключение реальных outputs | resilience, evidence, exports | подключение реальных outputs |
| 3:40–4:20 | интеграционное тестирование | исправления и performance | evals и исправления |
| 4:20–5:00 | README, слайд, demo lead | чистый воспроизводимый прогон | demo-запросы и объяснения |

## Контрольные точки

- **00:20:** схемы файлов заморожены.
- **01:30:** Frontend и AI работают на fixtures; Backend показывает первые признаки.
- **03:00:** Backend отдаёт первую полную выгрузку.
- **03:40:** end-to-end интеграция.
- **04:20:** feature freeze — только исправления.
- **04:50:** чистый прогон и генеральная репетиция.

## Критический путь

Обязательные CSV и объяснимые роли важнее AI-функций. Если возникает задержка:

1. Backend сохраняет роли, evidence и priority.
2. Frontend сохраняет поиск, top-list и ego-граф.
3. Agentic AI сокращается до пяти детерминированных tools с шаблонными ответами.
4. Infomap, сложные циклы и внешний LLM остаются улучшениями, но не блокируют сдачу.
